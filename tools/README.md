# 성능 및 기능 검증 도구 (Benchmarking & Verification Suite)

본 디렉터리는 시스템 파라미터 변경 시 성능 및 동작 변화를 정량적으로 검증하기 위해 제작된 단독 실행형 벤치마킹 스크립트 모음입니다. 별도의 컴파일 빌드 과정 없이 독립적으로 즉시 실행할 수 있습니다.

```bash
source /opt/ros/jazzy/setup.bash && source ~/ros2_ws/install/setup.bash
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
python3 tools/<도구_명칭>.py
```

> 일부 독립 검증 도구를 제외한 대부분의 스크립트는 전체 자율주행 스택(`navigation.launch.py`)이 정상 기동된 상태에서 실행해야 합니다.

| `map_quality.py <라벨>` | SLAM 위치 추정 누적 오차 및 지도 찌그러짐/흔들림 측정 | 전체 자율주행 스택 |
| `corridor_test.py [폭...]` | 통로 폭 규격별 직진 통과 가능 여부 및 주행 소요 시간 측정 | 전체 자율주행 스택 |
| `turnaround_test.py [폭...]` | 통로 내부 제자리 회전 가능 여부 검증 (오프셋 제어 스윕) | 시뮬레이터 단독 |
| `slam_accuracy.py` | 임무 수행 후 SLAM 추정 포즈 vs Gazebo 시뮬레이터 참값(Ground Truth) 정밀 비교 | 전체 자율주행 스택 |
| `stream_rates.py [초]` | 센서 카메라 스트림별 실제 퍼블리시 주기 및 타임스탬프 동기화 검증 | 시뮬레이터 단독 |
| `jump_check.py [초]` | TF 퍼블리셔 중복 등록 감지 및 좌표계(`map->odom`, `odom->base`) 불연속 점프 검출 | 전체 자율주행 스택 |
| `render_map.py` | `/map` 토픽 맵 데이터를 고해상도 PNG 이미지로 렌더링하고 프론티어 표시 | 전체 자율주행 스택 |
| `verify_frontier.py` | 현재 지도 기준 자율 탐사 목표 후보 지점(Frontier Candidates) 추출 및 유효성 검증 | 전체 자율주행 스택 |
| `dock_calib.py` | 도크 비전 인식 정밀도 및 회전 오프셋 보정 파라미터 도출 | 시뮬레이터 + 비전 검출기 |
| `dock_range.py` | 알루코 마커 검출 최대 거리·편차 및 인식 불가 사각지대 측량 (스윕 테스트) | 시뮬레이터 단독 |
| `dock_test.py [횟수]` | 반복 도킹 자동화 성공률 및 최종 접안 정렬 오차 정량 측정 | 전체 자율주행 스택 |
| `dock_bench.py [--jobs N] [--repeat N]` | 복수의 초기 조건(오프셋, 파라미터 오버라이드) 도킹 시나리오를 **병렬 동시 검증** | 단독 자동 기동 |
| `corridor_plan.py` | 통로 폭별 전역 경로 생성(Global Path Generation) 가부 검증 | Nav2 스택 활성화 |
| `stall_attribution.py` | 주행 정체 및 비정상 정지 구간의 원인 요소 분해 분석 (탐사/플래너/제어기/BT) | 전체 자율주행 스택 |
| `path_stability.py` | 전역 경로 헤딩 변화량 대비 각속도 제어 명령 부호 반전(진동) 빈도 측정 | Nav2 스택 활성화 |
| `wrongway.py` | 경로 요구 방향 대비 로봇 역방향 회전/주행 이상 현상 감지 | Nav2 스택 활성화 |

> **안내**: `corridor_plan.py`는 로봇을 실제 주행시키지 않고 `ComputePathToPose` 서비스 직접 호출을 통해 전역 코스트맵 격자 상의 경로 생성 유효성만을 즉시 검증합니다.

### 병렬 도킹 벤치마크 시험대 (`dock_bench.py`)

`dock_bench.py`는 타 스크립트와 달리 **자체적으로 인스턴스별 시뮬레이터를 자동 기동**합니다. 따라서 실행 전 메인 항법 스택이 꺼져 있어야 합니다.

도킹 전용 고속 런치 파일(`orinbot_navigation/launch/dock_bench.launch.py` — 시뮬레이터 + 카메라 + 마커 검출 노드만 포함, SLAM/Nav2 제외)을 다중 병렬 프로세스로 기동하여 각각 다른 초기 조건에서 도킹을 수행하고 결과를 종합 리포트 표로 생성합니다.

- **완전 이중 격리 네트워크 적용**: **`ROS_DOMAIN_ID`**(ROS 2 디스커버리) + **`GZ_PARTITION`**(gz-transport)을 동시 적용하여 멀티 인스턴스 간 간섭을 완벽히 차단합니다.
- **격리 상태 검증**: 각 도메인 영역에서 `/clock` 퍼블리셔가 1개씩만 조회되면 정상적인 격리 상태입니다.
- **컴퓨팅 자원 예산**: 인스턴스 1개당 약 **1 CPU 코어 / 1 GB RAM**을 소모하므로, `--jobs` 파라미터는 `nproc` 및 시스템 여유 메모리를 고려하여 지정하십시오.
- **합격 판정 기준**: 물리 동판 접합 허용 마진 오차 범위 (세로 ±48 mm / 가로 ±34 mm / 회전각 ±6.3°) 내 진입 여부.

```bash
python3 tools/dock_bench.py                 # 기본 테스트 케이스 묶음 (8개 항목) 실행
python3 tools/dock_bench.py --jobs 4        # 동시 실행할 병렬 인스턴스 개수 지정
python3 tools/dock_bench.py --repeat 3      # 케이스별 반복 횟수 지정
```

케이스 목록 구성은 스크립트 상단의 `CASES` 구조체에서 손쉽게 수정할 수 있으며, 스폰 오프셋 좌표 및 `docking.yaml` 파라미터 오버라이드를 동시에 지정 가능합니다.

## 측정 시 주요 주의사항

1. **CPU 사용률 측정 정확도**: 표준 `ps` CLI의 `%CPU` 수치는 프로세스 런칭 시점부터의 누적 평균값이므로 실시간 시나리오 구간 부하 측정에 적합하지 않습니다. `measure_load.py`는 `/proc/<pid>/stat`의 `utime + stime` 틱 차분을 직접 계산하여 정밀한 실시간 CPU 사용률을 도출합니다.
2. **RTAB-Map 자원 누적 주의**: 동일 세션에서 장시간 맵을 누적하면 노드 메모리 및 CPU 소모량이 자동 증가합니다. RTAB-Map 관련 비교 실험 시에는 매 측정 회차마다 스택을 완전히 재기동하십시오.
3. **테스트 시나리오 변인 통제**: 로봇의 물리적 한계로 인해 교착(Stall) 및 복구(Recovery) 동작이 빈번하게 발생하는 극단적 협소 통로(0.70 m 미만)는 측정 시나리오에서 제외해야 변인을 정확히 통제할 수 있습니다.
4. **순간이동(Teleport) 후 물리 안정화**: `turnaround_test.py` 실행 시 로봇을 원하는 위치로 직접 순간이동시키면 순간적인 정적 물체 관통 현상으로 인해 물리 엔진 오차(Impulse anomaly)가 발생합니다. 반드시 통로 외부에서 주행으로 진입시켜야 합니다.
5. **측정 스크립트 중복 실행 금지**: 복수의 테스트 스크립트가 동시에 내비게이션 액션 명령을 발송하면 액션 선점(Preemption) 현상으로 인해 검증 결과 데이터가 오염됩니다.
6. **위치 이동 후 ROS Event Spin 처리**: 포즈 이동 후 대기 시 단순 `sleep`을 사용하면 큐에 남아 있는 이전 오도메트리 데이터로 인해 검출 한계 데이터가 오염됩니다. 반드시 ROS 이벤트를 스핀(Spin)하여 메세지 큐를 처리해야 합니다.

## 성능 기준선 (Baseline Metrics)

### 개발 PC 기준 (상대 비교용 베이스라인)

| 항목 명세 | 정량적 측정 수치 |
|---|---|
| CPU / 메모리 사용량 | 평균 1.16 코어 / 1.38 GB RAM |
| SLAM 위치 추정 오차 | 중앙값(Median) 0.027 m (90% 신뢰구간 0.043 m) |
| `map->odom` 최대 맵 보정량 | 0.111 m |
| 도킹 정렬 오차 (`staged` 방식, 후진 — **현행 표준**) | 세로 +5.4 mm, 가로 +1.2 mm, 회전각 −0.05° |
| 도킹 정렬 오차 (`staged` 방식, 전진) | 세로 중앙값 2.6 mm, 가로 1.2 mm, 회전각 0.6° (평균 소요 25.6초) |
| 도킹 정렬 오차 (`smooth` 방식, 전진) | 세로 중앙값 20.3 mm, 가로 0.8 mm, 회전각 0.4° (평균 소요 8.6초) |
| 도크 비전 인식 정밀도 (0.65 m 시점) | 거리 오차 ~1 mm, 가로 ~0.6 mm, 회전각 ~0.01° |
| 도킹 정렬 오차 (`staged` 방식, 후진 — 연속 3회) | 세로 +3.0 / +6.2 / +7.0 mm, 가로 +1.1 / −0.3 / +1.4 mm |

> 동판 물리 접촉 허용치는 세로 ±48 mm / 가로 ±34 mm 입니다. 세부 도출 근거는 `docs/ros2-lessons.md` 제6장을 참조하십시오.
